# ZTW 账号注销

## 范围

本功能只增加注销入口、统一 API、账号生命周期校验和必需的数据清理。不修改行情、撮合状态机、交易收费、返佣金额/等级/算法或任何支付能力开关。

- Android / iOS：我的 → 设置 → 注销账号。
- Web：账户设置 → 注销账号；公开说明和申请入口 `/account-deletion`。
- 唯一业务实现：`services/api/app/services/account_deletion*.py`。
- 账号状态：`active → deleting → deleted`。用户表保留不可登录的内部 ID 占位，必要账务外键不被级联删除。

## 用户流程与 HTTP 契约

所有响应使用现有 `{code, msg, data}` 包装；详情以生成的 OpenAPI 为准。

| API `/api/user/account-deletion` | 身份与含义 |
| --- | --- |
| GET `/eligibility` | 当前登录；返回阻塞事项计数和需要明确同意的自动撤回/下架事项 |
| POST `/verify` | 当前登录 + ZTW 原密码；只验证，不执行注销；返回 10 分钟有效的删除专用 ticket |
| POST `/submit` | ticket + 严格布尔 `confirm: true`；事务内重新检查；无未结事项才受理 |
| POST `/status` | 同一 ticket；只返回处理状态和必要阻塞说明；验证起 7 天内可查 |

`verified / blocked / processing / completed` 是注销申请状态，不是订单或支付状态。
`processing` 不代表数据已删除；只有数据库清理和附件清理全部完成才返回 `completed`。

票据在服务端只存 SHA-256，不含登录权限，不进入 URL、日志或错误详情。客户端仅在最终确认后保存专用恢复凭据；密码不持久化。超时只用原票据查询，绝不自动重新提交。重新提交必须再次由用户明确确认，且仍受 10 分钟验证时限限制。客户端保存的用户 ID 只防止 A 账号的回执误退出 B 账号，不参与服务端鉴权。

注销接口成功和可预期错误均禁止缓存；参数校验失败不会回显密码、票据或原始请求正文。有效回执按服务端票据独立限流（每分钟 30 次），无效流量使用有界来源桶，不占用其他用户有效回执的查询额度。

当前版本使用 ZTW 密码复核，不声称有短信归属验证，也不把一次已有 KAI 登录当成注销二次认证。当前注册入口先建立本地密码账号再绑定 KAI；若历史迁移中存在没有可用本地密码的 KAI-only 用户，上线前需确认真实的身份恢复/人工隐私申请渠道。不能要求用户新注册来接管旧账号，不能以随机密码或伪验证码绕过复核。

## 业务保护

同时检查买家、商家两种身份。活跃算力、在途交付、争议、未结资金/提现/商家结算、待结返佣均不能因注销抹掉。订单的 `completed` 可能仍在服务期，要结合到期时间、资产和续费事实。所有钱包桶使用原精度检查，负数异常也需核对。

已付款且已入账的历史支付不阻塞。未付款的本地 `expired/canceled` 不代表上游已关闭：有未确认上游痕迹的 Qixiang 订单，以及未收到可信终态的 MaPay 历史订单，要先核对，不重开支付开关、不伪造退款、不自动清零。待处理事项仅提示，不由注销服务代替运营做账。

尚未成交的需求/报价/商品可在最终同意后撤回/下架。历史邀请资格和已产生的返佣事实不改写；新增邀请计提在账号生命周期边界停止向已注销账号产生新权益，不改变正常账号的规则。

管理员账号必须先交接权限，不通过普通用户入口直接注销。

## 并发与失败恢复

- 认证入口在 legacy JWT 分支之前检查账号状态；全部平台会话撤销，KAI 绑定票据和回跳不能恢复旧账号。
- SQLAlchemy 认证写入边界及新业务参与方使用条件 UPDATE 行锁，兼容 SQLite 不支持有效 `FOR UPDATE` 的情况；上传在写文件前取得同一账号锁。
- 受理先提交 `deleting` 和会话撤销，再执行可重试清理。异步清理前复核未结事项；如果出现延迟义务，保留身份并显示待核查，不假报完成。
- 文件清单与数据库清理同事务落盘。仅删除所属上传目录中经过白名单验证的文件；拒绝越界、符号链接、Windows junction 和其他用户路径。不递归删除上传根目录。
- 后台每 60 秒扫描已确认申请，失败请求延后 5 分钟重试。重启可恢复；没有确认过的 `verified/blocked` 申请不会被自动执行。
- `last_error_code` 只保存 `cleanup_retry_required` 或 `obligations_require_review`，不记录私有路径、SQL 参数或密码。持续失败必须由值班人员核查；不能手工把状态改为 completed 来清告警。
- 未识别的历史媒体文件/崩溃遗留临时文件会保守地留下待核查状态，不随意扩大删除路径。

## 数据清理及保留边界

清理登录标识与密码、头像、地址、实名记录和照片、普通银行卡敏感字段、身份绑定票据、账号通知、本人社区内容及附件、本人联系人副本、客服普通对话以及终态交付的 SSH 密文和缓存副本。对帖子使用内容已删除的占位，避免删除其他作者的评论；必要计数重新计算。

不删除其他账号、公共行情历史、订单金额、账务流水、返佣和结算事实。必要业务 ID、时间、金额、财务审核资料和他人历史争议陈述继续受原有业务授权/管理员权限约束，并不是公开保留全部个人资料。打款凭证与保留的审计自由文本可能包含个人信息，不能承诺数据库中所有个人信息即时彻底消失。

个人信息处理联系方式为 `+86 4001082026`。正式上线前，运营/法务仍须确认保留材料清单、用途、期限、访问权限及到期清理责任人。当前代码没有擅自设定统一法定保留年限或删除金融证据；没有上线批准不能宣传为已经完成全部合规。

备份遵循批准的保留周期，不因一个账号注销就破坏整库备份。任何备份恢复上线前，必须对照恢复点之后的注销记录重新应用账号失效和清理；不得让已注销账号因旧库恢复而复活。上述恢复核对是上线运维门禁，不是当前代码已自动跨备份执行的功能。

## 测试与发布

仅用内存 SQLite/独立临时上传目录和合成测试账号验证，绝不向云端测试用户调用注销接口。本次增量上线使用独立入口 `services/api/migrate_account_deletion.py`，只添加 `users.account_status`、`users.deleted_at` 和 `account_deletion_requests` 表及所需索引；老账号默认 active，原密码、手机号及其他业务数据不改写。重复执行无变化，已有 deleting/deleted 状态不会被重置。

脚本必须显式提供经核对的 `DATABASE_URL`，不读取 `.env`，不回退到默认 `wod.db`；支持既有 SQLite 文件和 PostgreSQL。缺少 users 表、新库、非兼容注销表会拒绝执行。迁移前先停止 API 写入并备份，批准后在既有服务的数据库配置和数据卷下执行；不得为本次上线运行包含旧资金/行情迁移的完整 `init_db.py`，也不要撤掉现有服务直接启动 uvicorn 的 entrypoint 覆盖。

```bash
# 在 services/api 内，DATABASE_URL 已由经批准的服务环境显式注入。
python migrate_account_deletion.py
python migrate_account_deletion.py --check
```

Docker 镜像包含 `/app/migrate_account_deletion.py`。执行一次性迁移容器时，应复用经核对的数据库环境与数据卷，并用 `--entrypoint python` 执行该脚本；不能使用镜像的默认初始化入口。`--check` 仅检查结构，结构未就绪返回非零，不写入数据。脚本错误不会输出数据库 URL、凭据或 SQL 参数。

针对性测试从 `services/api` 运行：`python -m unittest discover -s tests -p test_account_deletion_migration.py -v`。测试只创建内存/临时合成库，验证旧凭据与其他业务表/索引/触发器不变、二次迁移不变、外键与票据唯一约束、新表可用及失败回滚；不连接实际服务数据库。

发布前在测试副本验证迁移及外键完整性，并备份生产库。先部署带迁移和旧令牌拦截的 API，再发布 Web 和新签名 APK/IPA；前端构建成功不等于正式安装包已更新。本次开发不自动推送、部署或更改服务器环境。

不得把 API 回滚到不检查注销状态的版本，否则历史 JWT 可能重新获得权限。代码回滚也不能撤销已完成的用户删除；应保持兼容的状态拦截并前向修复。
